# Внешний наблюдатель через GitHub Actions

Статус: подготовлен локально; не опубликован и не запущен в GitHub.
Предлагаемый отдельный публичный репозиторий: 939sasha/control247-external-observer.

Сервер проверяется по ответу SSH каждые 5 минут, независимо от VDS и компьютера.
Две последовательные ошибки создают одно уведомление в собственном Telegram-боте;
успешная проверка после сбоя создаёт уведомление о восстановлении. Ответ SSH
подтверждает только внешнюю связность, не работу продуктов целиком.

В репозитории публикуется только общий код. Адрес VDS, токен собственного бота,
получатель и отдельный ключ шифрования задаются через GitHub Secrets.
Состояние хранится в одной служебной Issue как шифротекст AES-256-GCM;
открытые журналы, адреса и данные клиентов не публикуются. Кэш и артефакты
Actions не используются. Состояние сохраняется до отправки в Telegram;
неопределённая доставка повторно автоматически не отправляется.

Стандартные GitHub-hosted runners публичных репозиториев бесплатны.
Приватные репозитории и увеличенные исполнители этим вариантом запрещены.
Расписание GitHub может задерживаться и пропускать отдельные задания: это
не гарантия обнаружения сбоя ровно за 10 минут. После пропуска слота счётчик
неподтверждённых ошибок начинается заново. Для защиты расписания от отключения
после долгого отсутствия активности раз в неделю обновляется только служебный
файл observer-heartbeat.txt. Поэтому workflow имеет contents:write и issues:write
только в этом отдельном репозитории; код продуктов он не меняет.

Перед запуском требуется явное разрешение владельца на публикацию отдельного
репозитория, его служебные обновления и сохранение указанных Secrets в GitHub.
Инициализация Issue выполняется один раз из пустой схемы с новым ключом;
отсутствующее или повреждённое состояние не сбрасывается автоматически.
Живые cron-запуски, доставка из GitHub и длительная работа ещё не проверены.
